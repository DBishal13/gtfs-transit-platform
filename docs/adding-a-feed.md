# Adding a new transit agency's GTFS feed

This platform is built to hold more than one agency. Broward County Transit is
the default/demo feed, not a hardcoded assumption.

## Steps

1. **Get the feed.** Download the agency's GTFS static `.zip` (look for a
   "developer resources" or "open data" page, or search the
   [Mobility Database](https://mobilitydatabase.org/) / [transit.land](https://www.transit.land/)
   catalogs). It must be a real GTFS schedule feed per the
   [GTFS spec](https://gtfs.org/schedule/).

2. **Place it under `data/raw/<id>/gtfs.zip`.** Pick a short, lowercase,
   hyphenated `id` (e.g. `broward-bct`, `rvtd-or`).

3. **Register it in `data/feeds.yml`:**

   ```yaml
   - id: my-agency
     name: My Agency Transit
     region: My City, ST
     agency_timezone: America/New_York
     source_url: https://agency.example.com/gtfs.zip
     license: Public Domain (agency open data)
     raw_path: data/raw/my-agency/gtfs.zip
     census:                 # optional — omit for non-US feeds or to skip
       state_fips: "12"      # 2-digit state FIPS code
       county_fips: "011"    # 3-digit county FIPS code (the county the feed covers)
     ```

   Find FIPS codes via the [Census Bureau's reference tables](https://www.census.gov/library/reference/code-lists/ansi.html).

4. **Run the pipeline locally to check it works:**

   ```bash
   pip install -e ".[dev]"
   python -m pipeline.cli ingest my-agency        # fast sanity check
   python -m pipeline.cli all --feed my-agency     # full run, writes data/build/
   ```

   Population-weighted coverage requires a free Census API key — set
   `CENSUS_API_KEY` (sign up at https://api.census.gov/data/key_signup.html).
   Without it, coverage still works, just without population numbers.

5. **Commit `data/raw/<id>/`** (the raw feed) **and the `feeds.yml` entry.**
   Do **not** commit `data/build/` — it's regenerated by CI on every deploy.

6. **Add the repo secret** `CENSUS_API_KEY` under Settings → Secrets → Actions
   if you want population-weighted coverage in the deployed app (one-time, for
   the whole repo).

7. Push to `main`. `deploy.yml` picks up every feed in `data/feeds.yml`
   automatically — no other code changes needed for a well-formed feed.

## If the feed has data problems

The Data Quality dashboard is exactly for this — push anyway and check
`quality.json` / the DataQuality page. `pipeline/validate/quick_checks.py` and
the official `gtfs-validator` will surface referential-integrity issues,
coordinate problems, and spec violations without blocking the build.
